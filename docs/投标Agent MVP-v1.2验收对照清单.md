## 范围说明

以下旧验收项已移出 MVP1.2：

1. 生成结构化 `DraftBlock`。
2. 每个 block 回链矩阵项和证据。
3. 覆盖检查、事实校验和质量分。
4. 左右对照草稿审阅。
5. 草稿人工修改、block 审阅门禁和 Word 导出。
6. 同步/异步草稿生成任务。

这些能力不是删除，而是进入《投标Agent MVP-v1.3需求规划与开发进度》。

## 逐条说明

### #1 ContextPack 预览

- 接口：`POST /projects/{pid}/sections/{sid}/business-draft/context-pack/preview`。
- 返回：`profile_id`、`schema_version`、`readiness_status`、`context_json`、`outline_plan_json`。
- 验收重点：预览可在未确认前展示，但不能绕过后续确认门禁。

### #2 来源、矩阵、证据和风险可见

`context_json` 至少包含：

- `project_facts`
- `source_document`
- `matrix_summary`
- `matrix_items`
- `bound_evidence`
- `missing_facts`
- `qualification_decision`

`readiness_json.checks` 必须说明当前状态、原因和下一步动作。

### #3 资格门禁

确认 ContextPack 前必须满足：

1. 已运行资格预评估。
2. 已生成参标建议。
3. 参标建议已人工确认。

未满足时返回明确错误，前端应引导到资格预评估。

### #4 阻断项处理动作

每个阻断项都应能收敛到具体动作：

| 阻断类型 | 应引导到 |
| --- | --- |
| 缺资格预评估 | 资格预评估 |
| 参标建议未确认 | 资格预评估确认 |
| 矩阵未确认 | 合规矩阵审阅 |
| 缺企业资料证据 | 证据绑定/企业资料库 |
| 项目字段缺失 | 项目信息 |
| No-Go | 风险接受说明与内部草稿边界 |

### #5 去重与绑定后重评估

君山燃气项目暴露的问题纳入本轮验收：

1. 企业资质资料不能出现多个完全相同的候选。
2. 等价资料不能被重复绑定。
3. 人工绑定后，资格预评估应重新计算，不应继续显示为缺证据阻断。

当前实现同时执行两层去重：

1. 同一矩阵项内，等价资料只保留最新有效绑定。
2. ContextPack 全局证据汇总中，同一资料只展示一次，并聚合全部 `binding_ids` 和 `compliance_item_ids`。

### #6 ContextPack 确认和版本

确认 ContextPack 后：

1. 新包状态为 `confirmed`。
2. 章节上下文写入 `draft_section_context_packs`。
3. 同项目同标段旧包标记为 `superseded`。
4. 列表接口只返回有效包或明确区分状态。

### #7 缺事实表达

缺字段、缺证据和无法自动判定的事实只能进入：

- `missing_facts`
- readiness check
- SectionContextPack 的缺项说明

不得写成确定性结论。

## 验证记录

### 自动化

1. 后端完整测试：`140 passed`。
2. 后端静态检查：`ruff check app tests` 通过。
3. 前端生产构建：`npm run build` 通过。
4. 覆盖资格门禁、硬阻断拒绝、No-Go 风险快照、证据去重、绑定/解除后自动重评估、旧决策失效和 ContextPack 版本替换。

### 浏览器

1. 君山燃气：32 条矩阵全部确认，缺证据 0，完整预览显示来源、资格结论、矩阵、唯一证据、4 个待补事实和 20 章计划；预览后可确认。

4. 超过 1 小时未更新的后台任务会停止自动轮询并清除本地恢复状态；浏览器控制台无错误。

## 当前验收结论

MVP1.2 验收标准 #1-#10 已全部完成并通过自动化与真实项目浏览器验证。MVP1.3 可直接消费已确认的 ContextPack 和 SectionContextPack，草稿生成不再纳入 1.2 验收范围。
