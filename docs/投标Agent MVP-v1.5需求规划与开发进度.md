> 版本沿革：原 MVP1.4 的 RAG 证据增强规划，因易用性优化插入为 MVP1.4，整体顺延为 MVP1.5。

## 1. 版本目标

MVP1.5 的目标是把“人工找证据”升级为“系统推荐候选证据，人工确认后使用”。它不直接生成正式标书，也不替用户自动绑定证据。

本版本要解决：

1. 从企业资料库召回证照、人员、业绩、承诺、历史材料等候选证据。
2. 使用关键词检索、元数据过滤、pgvector 向量召回和 rerank 提升候选质量。
3. 给出命中片段、推荐理由、资料状态、权限和风险提示。
4. 用户确认后，证据进入 `bound_evidence`，再由 MVP1.2 ContextPack 和 MVP1.3 草稿链路消费。

## 2. 核心原则

1. RAG 是候选证据增强器，不是自动决策器。
2. 候选证据必须人工确认后，才能进入 ContextPack。
3. 检索结果必须带来源、页码、片段、权限、有效期和推荐理由。
4. 低置信度、权限不足、过期或冲突材料只能提示风险，不能自动绑定。
5. RAG 不可用时，手工证据绑定和 ContextPack 主链路仍应可用。

## 3. 不纳入 MVP1.5

以下能力不进入 MVP1.5：

1. 技术标核心章节生成。
2. 净化产品选型、参数匹配和候选配置。
3. 图纸/示意图辅助。
4. OCR 和复杂补遗版本链。
5. 多 Agent 编排。
6. 报价辅助、自动报名、自动签章和自动提交。
7. 未经人工确认的自动证据绑定。
8. 自动判断企业资质、人员、业绩真实性。

## 4. 主流程

1. 用户在矩阵项、资格项、缺证据项或 ContextPack 缺项上点击“推荐证据”。
2. 系统构建检索查询，包含条款文本、条目类型、项目地区、资料类型、权限和有效期约束。
3. 系统执行关键词检索、元数据过滤和向量召回。
4. 系统使用 rerank 对候选片段重排。
5. 系统展示候选证据、命中片段、推荐理由、风险和权限状态。
6. 用户绑定、拒绝或标记待补。
7. 已绑定证据进入 ContextPack 的 `bound_evidence`。
8. 被拒绝或低置信度候选进入评测样本和审计日志。

## 4.1 资料萃取管道：历史投标文件 → 企业资料库（P0，2026-06-07 决策）

把企业历史投标文件（Word / 文本型 PDF / 纯图扫描 PDF）萃取成结构化企业资料，作为 RAG 的语料供给侧——召回质量的天花板由资料库内容决定，故此管道为 RAG 前置必需，已决定并入 1.5 P0。

**流程**：上传历史文件 → 解析/OCR 转全文 → LLM 抽取多条结构化资料（带来源出处 + 置信度）→ 人工复核确认 → 确认后向量化落库 `EnterpriseMaterialChunk` → 供 RAG 召回。

**决策记录（2026-06-07）**

1. **OCR 选型**：纯图/扫描 PDF 用**阿里云 OCR「通用文字识别」（高精全文 + 表格识别）**转文本，再交 LLM 抽取。落地后端已预留的 `ParseTask.parser_type='ocr'`；多页 PDF 先用 pymupdf 逐页渲染成图再逐页 OCR 拼回全文。
   - **暂缓（第二阶段再做，但确定后续要做）**：阿里云**企业资质识别**（营业执照等单证模板识别，作精度增强）、**票证核验**（营业执照真伪核验，喂 `verification_status`）。
2. **抽取信任边界**（认同）：抽取只产出 `verification_status='pending_confirm'` 草稿，**必带来源（文件 + 页码 + 原文片段）+ 置信度**；人工确认后才转 `confirmed`，绝不自动可信。
3. **向量化时机**（决策）：**人工确认后才向量化落库**，不对未确认草稿建向量，保证召回语料干净。
4. **范围归属**：并入 **MVP1.5 P0**。

**复用 vs 新建**

- 复用：`parsers/pdf.py`(pymupdf)、`parsers/word.py`、`ParseTask` 异步解析框架、`llm_gateway` 调用/审计/降级范式、`EnterpriseMaterial` 既有字段（类型/证书号/发证机关/持有人/有效期/业绩项目名/金额/`structured_fields`/`evidence_text`）。
- 新建：阿里云 OCR 解析器（落地预留的 `'ocr'` 类型）、企业资料 LLM 抽取器（一份文件抽多条 + 出处 + 置信度）、跨历史文件去重合并、人工复核界面、确认后向量化。

## 6. 异常处理和收敛规则

| 场景 | 系统处理 | 是否允许自动绑定 |
| --- | --- | --- |
| 无检索结果 | 标记待补资料，保留人工上传入口 | 不允许 |
| 低置信度结果 | 展示为弱候选，提示人工核验 | 不允许 |
| 资料过期 | 标记过期风险，建议替换材料 | 不允许 |
| 权限不足 | 不展示敏感片段或仅显示脱敏摘要 | 不允许 |
| 索引过期 | 提示重建索引，候选结果标记过期 | 不允许 |
| Embedding 服务失败 | 降级关键词和元数据检索 | 不允许 |
| Rerank 服务失败 | 返回未重排候选并提示降级 | 不允许 |
| 候选与条款冲突 | 标记冲突原因，进入人工确认 | 不允许 |
| 同一证据重复命中 | 合并展示来源和命中原因 | 不允许 |

## 7. 验收标准

1. 企业资料可以完成索引重建，并展示索引版本、覆盖率和失败 chunk。
2. 指定合规矩阵项后，系统能返回候选证据、来源片段、资料状态和推荐理由。
3. 候选证据默认不自动绑定，必须由用户确认。
4. 权限不足、敏感、过期和低置信度材料不会进入可直接引用证据。
5. Embedding 或 rerank 不可用时，系统能降级并明确提示。
6. 绑定后的证据能进入 MVP1.2 ContextPack 的 `bound_evidence`。
7. 拒绝和替换候选证据会记录原因。
8. 固定评测样本能输出召回率、TopK 命中率、人工绑定率和误推荐类型。

## 7.1 工程约定（来自《RAG 前置地基梳理》）

1. **候选证据抽屉做成独立组件**：1.5 的候选证据 UI 必须新建独立组件（参照 `frontend/src/components/ContextPackPreviewDrawer.tsx`），不得继续堆进 `App.tsx`。
2. **检索网关与向量真实化在 1.5 内一次到位**（地基阶段已决定不前置）：
   - embedding/rerank 运行时网关复用 `llm_gateway` 的超时 / `model_invocation` 审计 / 失败降级机制；
   - 维度配置化，`search_material_hits` 改走 pgvector DB 端向量距离，新增 ANN 索引（ivfflat/hnsw）迁移，`embedding_vector` 列真正参与检索。
3. **纯逻辑单测**：新增前端纯函数（聚合/过滤/打分等）应补 `vitest` 单测（已建立 `frontend/src/pages/selectors.test.ts` 样板，`npm test` 运行）。
4. **OCR 凭证配置位**：阿里云 OCR AccessKey 通过 `.env` 配置（已新增 `ALIYUN_OCR_*` 配置项），凭证不入库不进日志；OCR/抽取调用复用 `model_invocation` 审计范式。
5. **抽取草稿与确认分离**：抽取产物一律落 `pending_confirm`，向量化/检索切片只发生在 `confirmed` 之后——确认动作是写库的唯一可信闸口。
