# 投标 Agent MVP-v1.3 需求规划与开发进度

> 更新时间：2026-06-04
> 当前阶段：需求边界已确认，待 MVP1.2 ContextPack 主链路稳定后启动
> 版本定位：RAG/Embedding/Rerank 增强。为 ContextPack 提供更好的企业资料证据候选，不直接替代人工确认，不直接生成正式标书。

## 1. 版本目标

MVP1.3 的目标是把“人工找证据”升级为“系统推荐证据，人工确认使用”。它是 MVP1.2 ContextPack 的上游增强能力，而不是新的生成主链路。

本版本要解决的问题：

1. 从企业资料库中自动召回与招标要求相关的证照、人员、业绩、承诺模板和历史材料片段。
2. 通过 embedding、pgvector、关键词检索和 rerank 提升证据候选的相关性。
3. 为每个候选证据给出推荐理由、命中片段、风险提示和权限状态。
4. 让用户可以绑定、拒绝或标记候选证据，并把确认后的证据回写到 ContextPack。

## 2. 核心原则

1. RAG 是证据候选增强器，不是自动决策器。
2. 候选证据必须人工确认后，才能成为 ContextPack 的 `bound_evidence`。
3. 检索结果必须带来源、页码、片段、资料状态、权限和推荐理由。
4. 低置信度、权限不足、过期或冲突的材料只能作为风险提示，不能自动绑定。
5. 检索不可用时，MVP1.2 的手工证据绑定和 ContextPack 生成链路仍应可用。

## 3. 不纳入 MVP1.3

以下能力不进入 MVP1.3：

1. 技术标核心章节生成。
2. 净化产品选型、参数匹配和候选配置。
3. 图纸/示意图辅助。
4. OCR、复杂补遗版本链。
5. 多 Agent 编排。
6. 报价辅助。
7. 自动报名、自动签章和自动提交。
8. 未经人工确认的自动证据绑定。
9. 自动判断企业资质、人员、业绩真实性。

这些能力继续进入长期规划，不排入具体 MVP 版本。

## 4. 前置依赖

MVP1.3 依赖以下能力：

1. MVP1.2 ContextPack schema 已稳定。
2. ContextPack 已区分 `bound_evidence`、`candidate_evidence`、`missing_facts` 和 `manual_notes`。
3. 企业资料库已有资料类型、权限等级、有效期、来源文件和基础切片。
4. 合规矩阵条目有稳定的条目类型、风险等级、来源原文和待响应文本。
5. 审计日志能记录候选证据推荐、绑定、拒绝和人工说明。

## 5. 主流程

MVP1.3 主流程如下：

1. 用户在矩阵项、资格项或 ContextPack 缺项上点击“推荐证据”。
2. 系统构建检索查询，包含条款文本、条目类型、项目地区、资料类型、权限和有效期约束。
3. 系统执行混合检索：关键词检索、元数据过滤、向量召回。
4. 系统使用 rerank 对候选片段重排。
5. 系统生成候选证据解释，展示命中词、语义匹配原因、资料状态和风险。
6. 用户绑定、拒绝或标记待补。
7. 已绑定证据进入 ContextPack 的 `bound_evidence`。
8. 被拒绝或低置信度候选进入审计和评测样本。

## 6. 需求范围

### P0：企业资料向量化和候选证据推荐

| 模块 | 需求 | 状态 | 说明 |
| --- | --- | --- | --- |
| 资料切片标准化 | 对企业资料按页码、段落、表格和资料类型生成 chunk | 未开始 | 复用现有文件和资料库模型 |
| Embedding 接入 | 接入 `BAAI/bge-large-zh-v1.5` 或同类中文 embedding 模型 | 未开始 | 支持配置、限流和失败降级 |
| pgvector 索引 | 建立向量字段、索引和重建任务 | 未开始 | 支持项目级和企业级资料过滤 |
| 混合检索 | 关键词、元数据过滤、向量召回组合检索 | 未开始 | 不只依赖向量相似度 |
| Rerank 接入 | 接入 `BAAI/bge-reranker-large` 或同类 reranker | 未开始 | 输出重排分数和原因 |
| 候选证据接口 | 按矩阵项返回候选证据、片段、来源和推荐理由 | 未开始 | 默认不自动绑定 |
| 人工绑定/拒绝 | 用户确认后绑定证据，拒绝原因写入审计 | 未开始 | 反哺评测样本 |

### P1：ContextPack 增强和质量评测

| 模块 | 需求 | 状态 | 说明 |
| --- | --- | --- | --- |
| ContextPack 候选证据区 | 在 ContextPack 预览中展示候选证据和确认状态 | 未开始 | 候选和已绑定证据明确分区 |

| 索引健康检查 | 展示索引版本、重建时间、失败 chunk 和资料覆盖率 | 未开始 | 避免使用过期索引 |

## 7. 异常处理和收敛规则

| 场景 | 系统处理 | 是否允许自动绑定 |
| --- | --- | --- |
| 无检索结果 | 标记待补资料，保留人工上传入口 | 不允许 |
| 低置信度结果 | 展示为弱候选，提示人工核验 | 不允许 |
| 资料过期 | 标记过期风险，建议替换材料 | 不允许 |
| 权限不足 | 不展示敏感片段或仅显示脱敏摘要 | 不允许 |
| 索引过期 | 提示重建索引，候选结果标记为过期 | 不允许 |
| Embedding 服务失败 | 降级关键词和元数据检索 | 不允许 |
| Rerank 服务失败 | 返回未重排候选并提示风险 | 不允许 |
| 候选与条款冲突 | 标记冲突原因，进入人工确认 | 不允许 |
| 同一证据重复命中 | 合并展示来源和命中原因 | 不允许 |

## 8. 数据与接口建议

建议新增或扩展以下对象：

1. `knowledge_chunks`：企业资料 chunk、页码、段落、表格、资料类型和权限。
2. `vector_embeddings`：embedding 向量、模型、维度、hash、索引版本。
3. `retrieval_queries`：检索请求、查询来源、过滤条件和用户。
4. `retrieval_results`：候选证据、分数、rank、rerank 分数和推荐理由。
5. `evidence_candidate_actions`：绑定、拒绝、忽略、替换和人工备注。
6. `knowledge_index_jobs`：索引重建任务、失败原因和覆盖统计。

API 形态建议：

1. `POST /knowledge-assets/{id}/index`
2. `GET /knowledge-index/status`
3. `POST /compliance-items/{id}/evidence-candidates`
4. `POST /draft-context-packs/{id}/evidence-candidates`
5. `POST /evidence-candidates/{id}/bind`
6. `POST /evidence-candidates/{id}/reject`
7. `GET /retrieval-evaluations/summary`

## 9. 验收标准

MVP1.3 可按以下标准验收：

1. 企业资料可以完成索引重建，并展示索引版本、覆盖率和失败 chunk。
2. 指定合规矩阵项后，系统能返回候选证据、来源片段、资料状态和推荐理由。
3. 候选证据默认不自动绑定，必须由用户确认。
4. 权限不足、敏感、过期和低置信度材料不会进入可直接引用证据。
5. Embedding 或 rerank 不可用时，系统能降级到关键词/元数据检索，并明确提示能力降级。
6. 绑定后的证据能进入 MVP1.2 ContextPack 的 `bound_evidence`。
7. 拒绝和替换候选证据会记录原因，用于评测和后续优化。
8. 固定样本评测能输出召回率、TopK 命中率、人工绑定率和误推荐类型。

## 11. 与长期规划的边界

MVP1.3 完成后，系统只具备更强的“找证据”能力，不代表已经具备以下能力：

1. 不自动生成技术标。
2. 不自动做净化产品选型。
3. 不自动生成图纸。
4. 不自动 OCR 扫描件。
5. 不拆多 Agent 平台。
6. 不做报价决策。
7. 不自动签章或提交。

这些方向仍需在样本、数据、专业责任和交付边界明确后，以长期专项方式重新评估。
