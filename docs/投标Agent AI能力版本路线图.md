# 投标 Agent AI 能力版本路线图

> 更新时间：2026-06-06
> 目的：明确 AI 能力在 MVP1.1 / MVP1.2 / MVP1.3 / MVP1.4 / MVP1.5 和长期规划中的边界。
> 核心原则：AI 可以扩大处理能力，但不能扩大责任边界。
> 当前状态：MVP1.1 P0 + P1 已完成主体开发；MVP1.2 聚焦 ContextPack 预览/生成/确认；MVP1.3 聚焦基于 ContextPack 的商务/资格草稿生成审阅；MVP1.4 聚焦易用性优化（不扩 AI 能力）；MVP1.5 聚焦企业资料 RAG、Embedding/Rerank 和候选证据推荐。技术标、净化产品、图纸/OCR、多 Agent 和报价辅助进入长期规划，不排入具体 MVP 版本。

## 1. 基本判断

投标是高精度、高风险、强合规场景。AI 在这个场景中最擅长的不是替人做最终决策，而是在复杂信息中完成定位、分类、对比、解释和草稿化。

项目核心不是自由聊天窗口，而是高质量的投标上下文工作台：

1. 文件有版本。
2. 条款有来源。
3. 证据有资料。
4. 上下文有边界。
5. 草稿有引用。
6. 风险有解释。
7. 动作有审批。
8. 过程有审计。

本项目对生成链路的最高指导原则是：

> 生成标书前的一切流程，都是为了给最终模型生成正式产出提供干净、完整、可追溯、可校验的上下文。

## 2. AI 能力分级

| 等级 | 能力类型 | 典型任务 | 风险判断 | 版本建议 |
| --- | --- | --- | --- | --- |
| L1 | 读取定位 | 找条款、找证据、找差异、找版本变化 | 低 | MVP1.1 |
| L2 | 分类排序 | 条款分类、证据排序、风险初判、处理优先级 | 低-中 | MVP1.1 |
| L3 | 解释建议 | 推荐原因、风险说明、审批摘要、下一步建议 | 中 | MVP1.1 / MVP1.2 |
| L4 | 受控草稿 | 商务/资格草稿、资料改写 | 中-高 | MVP1.3 起 |
| L5 | 自动决策/动作 | 审批、签章、提交、最终参标决策 | 极高 | 不做或长期禁止 |

等级越高，约束越强：

- L1/L2 必须回链来源。
- L3 必须基于已有上下文生成解释，不允许无来源发挥。
- L4 必须逐段引用证据，并经过事实校验和人工复核。
- L5 不进入近期产品范围。

## 3. AI 辅助任务清单

| 当前人工做的事 | AI 辅助方式 | 风险等级 | 控制措施 | 版本建议 |
| --- | --- | --- | --- | --- |
| 判断条款类型 | 模型语义分类，规则复核，低置信度人工确认 | 低 | 来源回链、置信度、人工确认 | MVP1.1 |
| 定位关键日期、资格项、否决项 | 模型抽取 + 规则校验 + 来源回链 | 低-中 | 关键字段人工确认 | MVP1.1 |
| 判断条款风险等级 | 模型初判，规则兜底 | 中 | 高风险必须人工确认 | MVP1.1 |
| 构建商务/资格 ContextPack | 汇总已确认矩阵、证据、无需绑定说明、资格结论和缺项 | 中 | 可预览、可确认、可审计 | MVP1.2 |
| 判断是否参标 Go/No-Go | 模型/规则生成建议和理由 | 高 | 最终参标决策必须人工确认 | MVP1.2 |
| 判断是否满足实质性响应 | 模型/规则初判 | 高 | 强制项、否决项人工复核 | MVP1.2 |
| 生成商务/资格章节初稿 | 基于已确认 ContextPack 分章节生成结构化稿 | 中-高 | 逐段引用来源，事实校验，人工审阅 | MVP1.3 |
| 把企业资料段落改写成标书语言 | 模型生成候选段落 | 中 | 事实校验拦截，保留证据引用 | MVP1.3 |
| 从企业资料中找证据 | RAG 检索 + 模型重排 | 低-中 | 只推荐候选，不自动绑定 | MVP1.5 |
| 比较招标要求和企业资料是否匹配 | 语义匹配和差异提示 | 中 | 不一致项人工确认 | MVP1.5 |
| 技术响应初稿 | 基于技术要求、产品目录、检测报告和历史方案生成候选 | 中-高 | 技术参数逐项回链，人工审核 | 长期规划 |
| 净化设备候选配置 | 结合产品目录和参数做候选推荐 | 高 | 只做候选，不做最终工程承诺 | 长期规划 |
| 自动报名、自动签章、自动提交 | 不允许模型执行 | 极高/禁止 | 明确不做 | 不进入路线图 |

## 4. MVP1.1：AI 做读标、拆分、分类和解释

MVP1.1 的目标是让 AI 进入受控的读标、拆分、分类、解释和审阅纠错任务。

已完成主体能力：

1. 模型配置中心。
2. PromptOps registry。
3. 合规矩阵 AI 抽取增强。
4. 结构化 schema 校验和规则降级。
5. 风险等级初判。
6. 矩阵审阅视图。
7. 人工划选补漏。
8. 相似补票。
9. 文本 Diff 高亮。
10. 重复项关联和级联确认。
11. 高风险、强制项、资格项确认防误触。

MVP1.1 不做：

1. 企业资料真实 RAG。
2. Embedding/Rerank。
3. 商务/资格正式草稿生成上下文确认。
4. 技术标核心章节生成。
5. 自动审批、自动提交、自动签章。

## 5. MVP1.2：ContextPack 预览、生成和确认

MVP1.2 的目标是把 MVP1.1 形成的“招标原文 + 合规矩阵 + 人工确认 + 已绑定证据 + 资格结论”转化为可预览、可确认、可审计的 ContextPack。

### 5.1 P0：ContextPack 主链路

1. 商务/资格生成上下文包：汇总项目基础信息、招标文件版本、已确认矩阵项、证据摘录、无需绑定说明、风险确认记录、资格预评估结果和待补充事实。
2. ContextPack 预览：生成前展示模型未来可使用哪些内容。
3. ContextPack readiness：输出 pass/warn/block、原因和处理动作。
4. 资格门禁：未运行或未人工确认参标建议时，不允许确认 ContextPack。
5. SectionContextPack：按章节拆分上下文范围和约束。
6. 审计快照：记录确认人、时间、来源版本和 readiness 结果。

### 5.2 明确不做

MVP1.2 不生成正文草稿，不生成 DraftBlock，不做覆盖检查、事实校验和 Word 导出。这些进入 MVP1.3。

## 6. MVP1.3：基于 ContextPack 的商务/资格草稿生成

MVP1.3 的目标是基于已确认 ContextPack 生成可审阅的商务/资格候选稿。

### 6.1 P0：分章节结构化生成

1. 目录/章节计划确认。
2. 分章节 prompt 和输出 schema。
3. 结构化 DraftBlock 生成。
4. 每个 block 回链合规条目、招标原文和企业证据。
5. No-Go 或 readiness block 只允许风险接受后的内部草稿。
6. 同步/异步生成任务和失败重试。

### 6.2 P1：生成后校验和审阅

1. 覆盖检查：强制项、高风险项、资格项覆盖率。
2. 事实校验：项目名称、日期、金额、证书编号、人员和业绩。
3. 左右对照审阅：正文 block 与合规条目双向定位。
4. 审阅状态：已覆盖、缺证据、待补事实、已批准、驳回。
5. 人工修改留痕。
6. 审阅通过后导出 Word。

MVP1.3 仍不做真实 RAG 和自动证据推荐。

## 7. MVP1.4：易用性优化

MVP1.4 不扩展 AI 能力边界，专注降低一线使用门槛，让 MVP1.3 已具备的草稿闭环"好用、能用、放心用"。

建议能力：

1. 首页项目列表治理（项目为主轴）：状态分组、搜索、分页，活跃项目易定位。
2. 术语白话化：把系统内部概念换成大白话，仅改前端文案，不动后端字段/模型/API。
3. 草稿审阅提效：状态过滤 + "必须原样写入的内容"逐条查看 + 受保护批量确认。
4. 异步任务等待体验：预计耗时/阶段说明 + 完成提醒。
5. 管理层宏观看板：经营级聚合指标，与一线操作视图分层。

MVP1.4 必须保留边界：

1. 不弱化任何既有质量门禁（事实核查、导出预检、No-Go 拦截、人工确认）。
2. 不改动后端数据模型与 API 语义。
3. 不新增 AI 自动决策能力。

详见 `docs/投标Agent MVP-v1.4需求规划与开发进度.md` 与 `docs/投标Agent 易用性优化方案.md`。

## 8. MVP1.5：企业资料 RAG 和候选证据推荐

MVP1.5 的目标是增强 ContextPack 的上游证据来源：系统从企业资料库推荐候选证据，用户确认后再进入 ContextPack。

建议能力：

1. 企业资料真实 RAG：中文 embedding + pgvector + rerank。
2. 企业资料索引重建和健康检查。
3. 候选证据推荐解释。
4. 企业资料与招标要求语义匹配。
5. 候选证据人工绑定、拒绝和替换。
6. ContextPack 候选证据区。
7. 权限过滤、敏感字段脱敏和过期风险提示。
8. 检索质量评测集。

MVP1.5 必须保留边界：

1. 候选证据不自动绑定。
2. RAG 失败不影响手工绑定和 ContextPack 主链路。
3. 未确认候选不得进入正式生成上下文。

## 9. 长期规划

以下能力不排入具体 MVP 版本，待样本、数据、专业责任和交付边界明确后再拆专项：

1. 技术标核心章节。
2. 净化产品目录和参数匹配。
3. 技术偏离分析和候选配置。
4. 检测报告、产品目录和历史方案绑定到技术响应项。
5. 投标阶段示意图。
6. OCR 和复杂补遗版本链。
7. 多 Agent 编排和 Agent 级审计。
8. 报价辅助。
9. 外部报名、签章和提交集成。

长期规划也必须保留边界：

1. 产品选型只做候选推荐，不做最终工程承诺。
2. 图纸只做投标阶段示意图，不替代正式设计图。
3. 技术参数偏离必须人工确认。
4. 最终技术方案必须由业务/技术负责人审核。

## 10. 明确禁止或长期不做的能力

以下能力不进入近期路线图：

1. 自动报名。
2. 自动签章。
3. 自动提交投标文件。
4. 自动替用户确认 Go/No-Go。
5. 自动通过审批任务。
6. 自动承诺产品参数、工期、金额、人员和证书信息。
7. 绕过人工确认直接修改正式投标文件。
8. 读取外部文件后自动执行高权限动作。

## 11. 推荐版本路线

| 版本 | 核心目标 | AI 能力边界 |
| --- | --- | --- |
| MVP1.0 | 建好投标上下文工作台和可信闭环 | 已完成；规则、检索、人工确认和审计为主 |
| MVP1.1 | AI 读标、拆分、分类、解释和审阅纠错 | 已完成主体开发；不接 embedding/rerank |
| MVP1.2 | ContextPack 预览、生成、确认和准备度门禁 | 只确认生成输入，不生成正文草稿 |
| MVP1.3 | 基于 ContextPack 的商务/资格草稿生成、审阅和导出 | 结构化稿必须引用证据，经过事实校验和人工审阅 |
| MVP1.4 | 易用性优化：首页治理、术语白话化、审阅提效、等待体验、管理看板 | 不扩 AI 能力边界，不改后端语义，不弱化既有门禁 |
| MVP1.5 | 企业资料 RAG、Embedding/Rerank、候选证据推荐和人工绑定 | 检索结果只做候选，人工确认后才能进入 ContextPack |
| 长期规划 | 技术标、净化产品、图纸/OCR、多 Agent、报价辅助 | 技术响应、参数匹配、候选配置和外部集成都需人工确认 |

当前最重要的判断：

> 先把上下文做干净，再让 AI 进来；先让 AI 帮人定位和对比，再让 AI 帮人草拟；永远不要让 AI 直接替人做最终承诺。
