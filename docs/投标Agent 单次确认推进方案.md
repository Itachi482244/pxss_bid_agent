# 投标 Agent：半自主推进 + 单次确认 方案

> 更新时间：2026-06-19
> 状态：产品方案已对齐（待转工程设计 / 代码改造）
> 背景：现有工作台是 7 步多阶段流水，每步都要人盯、人点，体验"阻塞"。本方案把人的介入压缩到**每个标段提交前的一次集中确认**，其余前置工作由 Agent 半自主完成。
> 关联：`docs/投标Agent 标书内容打磨主轴设计.md`、`docs/投标Agent 改造方案.md`、`backend/app/services/agent_assist.py`

---

## 0. 一句话目标

> 不是"把所有确认压成一次"，而是"**把人的介入压缩到不可省略的高风险决策上**，其余由 Agent 静默处理或批量预采纳"。人只在**每个标段生成标书前**集中确认一次（或修改后确认）。

核心安全前提贯穿全文：**最终审核只能发现它展示出来的东西**——所以废标级的项绝不允许被"自信"隐藏。

---

## 1. 目标主流程

```
准备(上传/解析/矩阵生成)
      │
      │  人手动点「开始让 Agent 推进」(保留人主导的起点)
      ▼
Agent 半自主推进(条款判断 / 缺口暴露 / 低风险放行 / 证据推荐与低风险绑定)
      │
      ▼
待最终确认  ──►  最终确认页(三区) ──►  确认锁定 ──►  生成标书 docx
      ▲                                      │
      └────────── 可撤回，回到编辑重生成 ◄──────┘
```

- **粒度：按标段**。每个标段是独立投标单元（独立投标、独立废标判定），各自确认一次。
- **触发：手动起点**。前置就绪后，由人点「开始推进」；点了之后 Agent 一路跑完到"待最终确认"，中途不再要人逐阶段点。
- **状态机**：`草稿 → Agent 推进中 → 待最终确认 → 已确认 → 已生成`（已确认可撤回）。

## 2. 八条已对齐的设计决策

### 决策 1：数据缺口 = 行内阻塞，不做前置完整度检查
- 放弃"先评估企业资料库够不够"的抽象前置，改为**把缺口挂在具体要求上**：
  - **绑定阶段**：明示"缺绑定材料"（需要企业证据但库里没有）→ 出路：上传。
  - **合规审阅阶段**：明示"缺判断证据"（有材料但不敢确认满足）→ 出路：人工核对 / 换绑。
- 两类缺口在 UI 上**分开**（动作不同：上传 vs 核对）。
- 每个缺口必须有**两条消除出路**：① 补 / 绑材料；② 人工标记"无需证据 / 不适用"（留痕，复用 `enterprise_evidence_not_required`）。否则"本就不需要证据"的项会永久卡死。
- **副产品**：未消除的阻塞数 = 该标段"就绪度"指标，自动算出、挂在条款上、可下钻。

### 决策 2：废标级永远可见，低风险才可静默放行
- 误判放行的本质是"被判成非风险 → 被隐藏 → 最终页看不到 → 兜底失效"。安全网的洞正好等于误判大小。
- 因此画线：
  - **永远可见（废标级，无论 Agent 多自信都进最终页）**：资格条件、强制 / 实质性响应条款、报价与商务承诺、投标截止 / 关键日期、需盖章 / 原件的硬性格式。
  - **可静默放行（低风险，自动通过 + 最终兜底）**：一般性叙述要求、非强制的格式建议、有明确来源且非强制的低风险条款。
- 这样"最后人工审核能发现误判"从**碰运气**变成**结构保证**。

### 决策 3：证据自动绑定的边界
- **硬门槛（任何档位都先过，沿用现有代码）**：只绑 `confirmed` 材料、数据级别允许、非过期 / 非冲突、等价材料去重。
- **按要求风险分流**：

  | 要求类型 | 绑定行为 | 归档 |
  |---|---|---|
  | 废标级要求的证据 | **乙：只推荐候选，人主动采纳才生效**（建议≠生效） | 🔴 红牌区 |
  | 低风险要求的证据 | **唯一强匹配 + 已核验 + 有效 → 静默绑定** | ⚪ 已自动完成 |
  | 多候选 / 弱匹配 / 材料有瑕疵 | 不自动绑，降级为**阻塞**让人选 | 🔴 红牌区 |

- 原则：**唯一强匹配才敢自动；一旦歧义（多个都像）就交给人，绝不替人猜。**

### 决策 4：粒度与触发
- 粒度 = **按标段**各确认一次。
- 触发 = **保留手动「开始推进」起点**（让人有主导感），之后 Agent 自动跑完前置。

### 决策 5：修改后 / 重跑行为
- 人在最终页的动作分两类：
  - **补救型**（补材料 / 标记无需证据 / 选候选）→ **定向重评**：只重算"这一条要求 + 它直接影响的汇总（如资格 Go/No-Go）"，**不全量重跑、不碰无关项**（避免 ping-pong）。
  - **拍板型**（确认风险项 / 否决条款）→ **终局冻结**，Agent 不再评估、不覆盖。
- **已人工确认的项默认冻结**；Agent 重跑不许悄悄重开或覆盖。
- 跨会话重跑遇"已确认但底层结论变了" → **丙：保留确认状态 + 标记「⚠ 结论已变化，请复核」**，拎进最终页让人定夺（不悄悄放行、也不粗暴清空）。

### 决策 6：最终确认页（三区）+ 两步生成 + 可逆
```
┌─ 就绪度条：还差 N 项可生成 ─────────────────┐
│ 🔴 红牌区（必须清零才能生成）                  │
│    缺材料 / 缺证据阻塞 · 废标级待拍板           │
│    废标级证据候选（待采纳）· ⚠结论已变化请复核  │
│ 🟡 预采纳区（默认折叠，可展开抽查 / 批量改）     │
│    中风险条款、已预采纳项                       │
│ ⚪ 已自动完成（只读摘要 + 数量，可逐条下钻）     │
│    低风险放行 N 条 · 静默绑定 M 份              │
│            [ 确认锁定 ] → [ 生成标书 ]          │
└────────────────────────────────────────────┘
```
- 人打开**只盯红牌区**，处理完即可生成；黄 / 白区"想看才看"。
- **每条自动决策都能一键下钻看"为什么 + 来源"**（这条承诺依赖决策 8 的可解释引擎）。
- **生成 = 两步**：先「确认锁定」决策（可预览决策清单），再「生成标书」。
- **可逆**：确认后到正式提交前仍可"撤回 → 回到编辑 → 重新生成"（贴合投标"生成—自检—微调"的实务节奏）。

### 决策 7：现有多阶段 UI 的去向（选乙）
- **主线极简四态**：准备 → 推进 → 最终确认 → 生成。
- 旧阶段视图（合规矩阵 / 资格 / 技术 / 证据明细等）**降级为"按需下钻的只读详情"**，不再是必经步骤——日常不打扰，排查 / 审计随时可查（保留可追溯性）。

### 决策 8：判断引擎与 LLM 定位
- **规则 + 检索 = 硬闸**：条款是否满足、资格评估、缺口判定、绑哪份候选，都走规则 / 结构化数据 / 检索。可解释、可复现、可写回归测试——这是"低风险敢静默放行"和"下钻看为什么"的前提。
- **LLM 只做两件确定性之外的事**：① 招标原文抽取 / 归一成结构化要求（抽取阶段，有人校验）；② L4 叙述骨架润色（本就进人工审阅）。
- **核心红线 —— LLM 只能加保险，不能减保险**：
  - 允许：LLM 把某条**从"通过"升级为"需人看"**（发现规则漏掉的额外风险）。
  - 禁止：LLM 把废标级**从"需人看"降级为"静默通过"**。
- 推论：低风险项可交 LLM 判（错了成本可接受 + 兜底）；废标级谁判都一样要进最终页。

### 决策 9：低风险"静默放行"的准入条件（宁严勿松）
"属于低风险类别"≠"能静默放行"。一条低风险条款必须**同时满足以下全部 6 条**才允许 ⚪ 静默：
1. 类别属于低风险（非废标级）；
2. 有明确原文来源（能定位招标原文，不凭空判定）；
3. 非强制 + 非高风险（`is_mandatory=false` 且 `risk_level≠high`）；
4. 证据条件已闭合（需证据则已绑有效证据；不需证据则直接可放）；
5. 抽取阶段未标"需人工复核"；
6. 置信度 ≥ 阈值（初始沿用 `AUTO_PASS_CONFIDENCE ≈ 0.88`）。

任一不满足 → 不静默，降级到 🟡 预采纳或 🔴 红牌。**取向偏严起步**（静默是唯一人看不到的动作，错了无兜底），上线后看"人工推翻率"再考虑放松。

### 决策 10：🟡 预采纳区的定义与行为
- **归类**：
  - 低风险 + 完美（满足决策 9 全部）→ ⚪ 静默；
  - 低风险 + 有瑕疵但不致命（置信中等 / 证据强匹配但非唯一 / 来源略弱，且非硬缺口硬歧义）→ 🟡 预采纳；
  - 废标级 / 硬缺口 / 歧义 → 🔴 红牌。
- **行为**：Agent 已做决定，默认勾选"已采纳"；最终页**默认折叠、可见**，人可展开抽查 / 单条改 / 批量保持。
- **可见但不强制看**：人不动它，随「确认锁定」一并生效；**不设独立确认闸**（与确认锁定重复），**不阻塞确认**（只有红牌阻塞）。

### 决策 11：推进过程的进度与通知
- **后台不阻塞**：点「开始推进」后是后台任务（复用 `AsyncTask`/Celery），人可离开 / 关页面，完成后回来。
- **防重复**：一个标段同时只允许一个推进任务（active 唯一索引兜底）。
- **进度展示 = 甲（详细实时）**：当前步骤 + 已处理 N / 总 M 条 + 当前在判条款，让人看得到 Agent 在干活（符合"人主导"体感）。
- **完成**：应用内通知 + 标段状态置"待最终确认" + 预览数字（如"🔴 8 项"）+ 一键进入最终确认页。
- **失败**：整体回滚到推进前（不留半成品），给原因，可重试。
- 邮件 / IM 通知以后再说，先做应用内。

### 决策 12：多标段汇总视图（项目首屏）
- **进入项目即看到标段汇总**（主线首屏）。每个标段一卡 / 一行：名称、状态（草稿 / 推进中 / 待最终确认 / 已生成）、就绪度（🔴 红牌数，0 即可生成）、投标截止时间、主操作按钮（随状态变：`开始推进` → `去确认(N)` → `生成 / 下载`）。
- **顶部项目级汇总条**：如"3 个标段待确认 · 1 个已就绪 · 最近截止 6/25"。
- **排序 = 甲（紧急度综合）**：临近截止 + 红牌多优先；同项目内截止相同时自然退化为按红牌数排，跨项目 / 截止不同时正确拉开。

### 决策 13：截止时间的数据建模
- 投标实务：同一招标项目下**多标段同时招标是常态**；**同一份招标文件各标段截止时间不同是少数例外**（真不同时通常已拆成独立招标公告）。
- **建模在标段层，默认继承项目层统一值**，个别标段可覆盖。覆盖 99% "都一样" + 容纳少数 "不一样"，成本几乎为零。现有 `_deadline_for(project, section)` 已按 (项目, 标段) 取，方向一致。

## 3. 贯穿全程的护栏（不可为省事丢弃）

1. **不臆造**：缺事实 / 材料留可见占位或标缺口，绝不编。
2. **废标项永远可见**：再怎么自动，废标级必须在最终页暴露。
3. **建议≠生效的边界上移**：不是取消人工确认，而是把它从"每阶段多次"收敛为"提交前一次集中拍板"。
4. **可追溯**：每个自动决策可一键下钻看"为什么 + 来源原文 + 置信度"。
5. **判断不了默认进阻塞**：保守兜底，绝不默认放行。
6. **自动放行精度对废标级要求接近 100%**：上线后盯"人工推翻率"校准阈值。

## 4. 与现有系统 / 改造方案的对应

- 本方案是把 `agent_assist` 从"生成清单、人逐项处理"升级为"Agent 自动处理 + 绑定，产出单一提交前总确认"。
- 三档分流（静默 / 预采纳 / 必须拍板）直接对应 `docs/投标Agent 改造方案.md` 的 **`ActionPolicy`（auto / human / deny）**：
  - 🔴 红牌区 = `automation: human`（废标级 `requires_source_verified`）。
  - 🟡 预采纳 = `auto` + `pre_accepted`（可撤销）。
  - ⚪ 已自动完成 = `auto`（静默）。
- 复用现有件：`AgentReviewItem`（产物）、`AsyncTask`（推进任务）、`QualificationEvaluation`、证据绑定硬门槛、`enterprise_evidence_not_required`（"无需证据"出路）、`confirmation_stale`（决策 5 丙的实现基础）。

## 7. 工程设计与任务拆解

> 本节把上面 13 条产品决策落成工程蓝图（数据模型 / 状态机 / 后端组件 / API / 前端 / 任务拆解），仍不写实现代码。命名为建议值，落地时可调。

### 7.1 标段推进状态机

现有 `BidSection.status`（`draft/pending_files/parsing/pending_confirm/need_materials/confirmed/exported/archived`）是**导入解析生命周期**，不要overload。新增一个**独立维度** `assist_stage` 表达"半自主推进"主线（决策 4）：

```
not_started → advancing → awaiting_confirm → confirmed → generated
                  ▲                                │
                  └────────── unlock(撤回) ◄────────┘   (决策6 可逆)
```

- `not_started`：前置就绪、等人点「开始推进」。
- `advancing`：Agent 后台推进中（决策 11）。
- `awaiting_confirm`：推进完成，进最终确认页（决策 6）。
- `confirmed`：人已「确认锁定」，预采纳一并生效（决策 10）。
- `generated`：已生成标书 docx。
- 撤回：`confirmed → awaiting_confirm`（生成前后均可，重新编辑后再确认）。

转换守卫：`awaiting_confirm → confirmed` 仅当**红牌区清零**（决策 6）。

### 7.2 数据模型变更

| 表 | 变更 | 对应决策 |
|---|---|---|
| `bid_sections` | 新增 `assist_stage`（状态机）；新增 `bid_deadline`（可空，空则继承项目） | 4 / 13 |
| `projects` | 确认/新增项目级 `bid_deadline` 作为标段默认 | 13 |
| `agent_review_items` | 新增 `tier`（`silent`/`pre_accepted`/`blocking` ↔ ⚪/🟡/🔴）、`is_disqualifying`（废标级）、`conclusion_changed`（丙：结论变化待复核）、`auto_applied`（静默/预采纳是否已生效） | 2/3/5/9/10 |
| `agent_review_items` | 放宽 `step` CHECK 以容纳新步骤（如 `coverage`/`pricing`），或保持现三步 | — |
| 新表 `section_confirmation`（可选） | 记录「确认锁定」事件：confirm 时间、快照、是否已撤回，用于可逆 + 留痕 | 6 |

> 证据绑定无需新表：低风险静默绑 = Agent 直接建 `compliance_evidence_binding(status=active)`；废标级 = 只产 `agent_review_item(action=accept_evidence_binding)`，沿用现有人工采纳路径（决策 3）。

```
  classifier.py        # 单条要求/证据 → tier + is_disqualifying + reasons
  orchestrator.py      # 替代/包裹 execute_agent_assist_task：跑步骤→分档→
                       #   静默&预采纳自动生效、废标级产建议、发进度(决策 4/11)
  reeval.py            # 定向重评：单要求 + 直接汇总(资格Go/No-Go)，不全量(决策 5)
  final_review.py      # 聚合三区 payload（红/黄/白 + 就绪度）(决策 6)
  progress.py          # ProgressReporter：步骤+已处理N/总M+当前条款(决策 11)
```

- **分类引擎 `classifier`** 是核心：吃一条 `ComplianceItem`/证据候选，输出 `(tier, is_disqualifying, reasons, confidence)`。复用现有 `_matrix_escalation_reasons`/`_severity_for_item`/`_is_technical_item`/`requires_enterprise_evidence` 的信号，按决策 2/9/10 重组为三档。
- **LLM 接入点**（决策 8）：仅在 `classifier` 里作为"加保险"——可把某条从 `silent`/`pre_accepted` **上调**到 `blocking`，**禁止下调**;以及抽取阶段与 L4 润色。代码层加断言：LLM 输出只能提升 tier，不能降低。
- **定向重评 `reeval`**：被"补救型"动作（补材料/标记无需/选候选）调用，只重算该要求及其资格汇总；"拍板型"动作只改 `agent_review_item.status=accepted` 并冻结。

### 7.7 复用与迁移

- **强复用**：`AgentReviewItem`/`AsyncTask`/`QualificationEvaluation`/`QualificationDecision`/证据绑定硬门槛/`enterprise_evidence_not_required`(无需证据出路)/`confirmation_stale`(决策5丙基础)/`format-docx` 导出(生成)。

### 7.8 工程风险与护栏

1. **tier 误分类**：废标级被误判成 silent/pre_accepted = 静默放行废标 → 用决策 2"废标级永远 blocking"作硬规则前置，classifier 对 `is_disqualifying` 命中者**强制 tier=blocking**，不受置信度影响。
2. **定向重评的连锁**：限制只重算"本要求 + 直接汇总"，并对资格 Go/No-Go 这类汇总做幂等重算，避免 ping-pong（决策 5）。
3. **LLM 越权下调 tier**：在 classifier 出口加断言 + 测试，LLM 只能提升 tier。
4. **撤回后重生成**：`unlock` 必须使旧 docx 失效/标记过期，避免提交到旧版本。
5. **多标段并发推进**：沿用 active 唯一索引，按标段隔离。
