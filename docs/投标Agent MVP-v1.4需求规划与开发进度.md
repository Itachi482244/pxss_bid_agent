# 投标 Agent MVP-v1.4 需求规划与开发进度

> 更新时间：2026-06-06
> 当前阶段：P0 + P1 前端开发完成，待浏览器验收；P2 暂缓
> 版本定位：易用性优化（usability）。在 MVP1.3 已具备 ContextPack 驱动草稿闭环的基础上，降低一线使用门槛，让现有能力"好用、能用、放心用"。
> 版本沿革：本版本由《投标Agent 易用性优化方案.md》的讨论结论收敛而来；原 MVP1.4 的 RAG 证据增强规划顺延为 MVP1.5。
> 关联文档：详见 `docs/投标Agent 易用性优化方案.md`（评估与决策记录）。

## 1. 版本目标

MVP1.4 不扩展 AI 能力边界，专注把现有流程做得更易用：

1. 让用户进入系统后**快速定位活跃项目、清楚下一步该做什么**。
2. 把系统内部术语**换成大白话**，降低理解与培训成本。
3. 让**草稿审阅与"必须原样写入的内容"确认**更高效、且保留安全性。
4. 改善**异步任务等待体验**。
5. 为管理层提供**宏观经营看板**，与一线操作视图分层。

## 2. 核心原则

1. 只优化"面向用户的展示与交互"，**不改动后端数据模型、字段名和 API 语义**，避免牵动既有逻辑与测试。
2. 不弱化任何既有质量门禁（事实核查、导出预检、No-Go 拦截、人工确认）。
3. 全角色覆盖：一线投标专员、标书复核/审核、项目/部门负责人、企业资料/资质管理员，以及"一人多角色"的小团队。
4. 操作型视图（一线）与管理型视图（看板）分层，互不干扰。
5. 易用性改动以"低风险、可增量上线"为先，能拆小就拆小。

## 3. 不纳入 MVP1.4

1. RAG / Embedding / Rerank 与候选证据推荐（移至 MVP1.5）。
2. 技术标核心章节生成、净化产品选型、图纸/OCR、多 Agent、报价辅助（长期规划）。
3. `App.tsx` 大规模工程拆分（P2，暂缓，不进本版本排期；新功能开发时可顺手收敛）。
4. 任何新增的 AI 自动决策能力。

## 4. 用户画像与角色（决策依据）

| 角色 | 主要诉求 | 主视图 |
| --- | --- | --- |
| 一线投标专员 | 写标、绑定资料、生成与审阅草稿 | 操作型（项目 + 待办） |
| 标书复核/审核人 | 把质量、审阅拍板 | 操作型（审阅聚焦） |
| 项目/部门负责人 | 看进度、做参标决策 | 操作型 + 看板 |
| 企业资料/资质管理员 | 维护证据库 | 资料维护 |
| 老板/管理层 | 掌握整体经营信息 | 管理型宏观看板 |
| 一人多角色（小团队） | 不区分分工，全流程自助 | 操作型 + 看板 |

## 6. 异常处理和收敛规则

| 场景 | 系统处理 |
| --- | --- |
| 术语白话化与既有文案冲突 | 以术语对照表为准统一替换，保留旧字段语义不变 |
| 批量确认含未查看项 | 阻止批量，明确提示需先逐条查看 |
| 看板指标缺数据源（如中标结果） | 指标置灰或标"暂无数据"，不臆造；按需新增录入入口 |
| 异步任务无法估时 | 显示阶段说明而非具体时间，避免误导 |
| 跨项目待办聚合为空 | 显示空状态引导，而非空白 |

## 7. 验收标准

1. 首页以项目为主轴，支持状态分组、搜索、分页，活跃项目可在长列表中快速定位。
2. 每个项目行能看出"当前阻塞/下一步"，并一键直达对应操作页。
3. 主要界面术语完成白话化替换，专业概念处有可查阅的解释，且后端字段/API 未改动。
4. 草稿块列表可按状态过滤；"必须原样写入的内容"支持逐条查看，批量确认仅对已查看项生效，未查看项被阻止。
5. 既有质量门禁（事实核查、导出预检、No-Go 拦截）行为不变。
6. 异步任务有预计耗时/阶段说明与完成提醒。
7. 管理层可进入宏观看板查看经营级聚合指标，缺数据指标明确标注。

### 实现要点与已知取舍

1. "下一步"与项目分组、管理看板均为**前端基于 `ProjectSummary` 既有字段推导/聚合**，未改后端 API 与数据模型。
2. 术语白话化集中在 `frontend/src/i18n/glossary.tsx`，仅改展示层；后端字段名、code、筛选 value 保持不变。
3. 受保护批量确认作用于"本章节"的待确认指定内容；批量"确认"要求全部已查看，"驳回"为逐条且必填原因（未做批量驳回，安全性已覆盖）。
4. 既有质量门禁（事实核查、导出预检、No-Go 拦截、`needs_confirm` 导出阻断）逻辑未改动。
5. 管理看板的"参标建议分布/中标率/中标趋势"因暂无对应数据源，按异常规则置灰为"暂无数据"。
